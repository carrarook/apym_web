# Gymkhana i18n Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Localize the entire Gymkhana app in Brazilian Portuguese and English with pt-BR default and a persistent locale selector.

**Architecture:** Use `next-intl` with the existing route URLs. Resolve a validated locale from a long-lived `NEXT_LOCALE` cookie for server rendering and provide messages to client components. Split messages by product area and keep locale-independent business/API values intact.

**Tech Stack:** Next.js 16 App Router, React 19, `next-intl`, TypeScript, Jest.

**Spec:** `docs/superpowers/specs/2026-11-17-gymkhana-i18n-design.md`

## Global Constraints

- `pt-BR` is the default locale; `en` is the only alternate locale.
- Keep existing route URLs, auth, business rules, API contracts, and stored domain values unchanged.
- Persist locale with a validated `NEXT_LOCALE` cookie using `SameSite=Lax` and a long lifetime.
- Translate all user-facing screens and shared components, including the member portal, booking/widget, settings, legal pages, validation, errors, and empty/loading states.
- Preserve pre-existing worktree changes; do not rewrite unrelated staged files.
- Project requires Node >=24 and npm >=10; verify with Node 24.

## Review Focus

- Missing or mismatched translation keys: test catalog parity and fail on missing keys.
- Missing, invalid, or unsupported locale cookies: test resolution falls back to pt-BR.
- Locale changes on server-rendered pages: test selector persists and refreshes the current route.
- Dates, numbers, and currency rendered in either locale: test representative formatting without changing underlying values.
- API error codes and user-authored content: confirm locale work does not mutate API contracts or translate dynamic user data.
